# AUV 您吃了么 — 全 App 产品审计报告

> 审计日期：2026-10-24。以资深产品经理视角，覆盖主页面、二级页面与三大核心流程（热量识别 / 详情→采购清单 / 一餐套餐）。
> 优先级：**P0** 影响核心功能正确性与可用性；**P1** 明显体验缺陷；**P2** 打磨项。

---

## 一、总体结论：五大系统性问题

1. **主题体系三套并存，深色模式大面积失效**
   硬编码浅色、`AppColors`、`ThemeManager` 三种写法混用。HistoryPage、FavoritesPage、FolderDetailPage、RecipeDetailSheet、ExportShoppingListDialog、StartupPage 以及清空历史/删收藏夹弹窗、FavoriteToast、RecipeCard 均存在硬编码浅色，深色下刺眼或不可读。

2. **空态普遍缺失或没有引导 CTA**
   探索无命中、食材搜索无命中、收藏/历史/收藏夹为空、套餐约束过严得到 0 道菜，这些场景要么整块空白，要么一句文案，没有「去逛逛 / 清除筛选 / 放宽约束」等下一步动作。

3. **破坏性操作缺少确认与可撤销**
   清空历史/收藏/今日菜单无二次确认；关闭「保留本地数据」立即清空收藏与历史；取消收藏立即从收藏夹移除；识别结果页返回直接丢弃结果；套餐「移除」无撤销。

4. **命名与文案不一致**
   「今日菜单 / 今日餐桌 / 加入今日餐桌」三种叫法混用；「严格模式」与 Toast「严格匹配」「仅限现有」不统一；「完成」实为关闭；「重新识别」实为回到相机；「帮我随机搭配一餐」实际只挑一荤一素食材。

5. **采购清单链路存在正确性缺陷**
   缺料永远对比首页「冰箱」选料（收藏夹/文件夹页传空数组，导致永远全量缺料）；详情内无可勾选库存；导出图片超出高度静默截断、页脚仍写「共 N 项」；聚合清单忽略已有库存。

### 2.3 核心流程

#### 热量识别（CalorieScanPage → FoodRecognitionService → HybridRecognizer）

| 优先级 | 问题 | 建议 |
|------|------|------|
| P0 | 手动/云端未命中时静默套用 100/150 kcal 占位，无「估算」标识 | 标注估算并可编辑 |

## 三、建议修复顺序（P0 优先）

1. **主题统一**（横切最高频、回报最大）：抽取统一主题 token 应用方式，批量替换 HistoryPage / FavoritesPage / FolderDetailPage / RecipeDetailSheet / ExportShoppingListDialog / StartupPage / 各弹窗 Toast。
2. **采购清单正确性**：缺料对比统一走库存，收藏夹/文件夹页正确传入；导出溢出提示；详情内可勾选。
3. **破坏性操作确认**：清空历史/收藏/今日菜单、关闭保留本地数据、取消收藏、返回丢弃识别结果，统一加确认。
4. **识别链路**：估算标识、超时/取消/重试、口径说明。
5. **一餐套餐**：空态、锁定语义、厨具约束持久化。
6. **文案/命名统一**：今日菜单、匹配模式、按钮语义、空态组件。
